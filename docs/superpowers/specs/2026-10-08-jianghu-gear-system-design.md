# 江湖 · 装备与器物系统 — 设计文档

- 日期：2026-10-08
- 范围：`淘金矿工小屋/jianghu.js`、`淘金矿工小屋/wuxia-content.js`、`淘金矿工小屋/淘金矿工小屋·自律工作台.html`
- 所属序列：江湖扩展子项目 1 / 4
- 前置：子项目 0（江湖初版，已完成并通过 70 项断言验证）

## 1. 背景与目标

### 问题

`state.jianghu.taels`（银两）目前只有一个出口：`learn()` 里的武学消耗
（`learnCost = cost.taels × 目标层数`）。学满本门武学后银两只进不出，
经济循环断裂——玩家继续闯荡、打赢切磋所积累的银两不再有用途。

### 目标

1. **主目标**：给银两一个持续的出口，让"闯荡 → 有收获 → 变强"形成正循环。
2. **次目标**：让战力构成不止"武学等级"一项——目前 `power()` 几乎只由
   四维与两门主修武学决定，装备提供一个可规划的成长维度。

### 硬约束

1. 不破坏「时辰只来自真实打卡」的核心前提（见 `jianghu.js` 顶部注释）。
2. 门派加成与宠物伙伴加成的既有规则不变（`stats()` 的叠加语义保持可预期）。
3. 现有存档不能坏：新增字段必须能被 `ensureFields` 补默认值，旧存档引用的
   内容被删除时必须由 `sanitize()` 自愈（不出现整页白屏）。

## 2. 已确认的设计决策

| # | 决策 | 选定 | 被否备选与理由 |
|---|---|---|---|
| D1 | 获取途径 | **掉落 + 商城补货** | 纯掉落：银两仍无出口，不解决主目标。纯商城：缺江湖感。打造（材料+配方）：加两套数据，留到后续轮次。 |
| D2 | 加成接入 | **并入四维属性**（进 `stats()`） | 只加战斗维度：风险最低，但玩家选择了更强的成长感。**已接受的后果**：装备可帮玩家越过事件的属性门槛。 |
| D3 | 形态 | **背包 + 手动穿戴 + 强化升级** | 自动装备：银两出口只是一次性换代，买齐即再次断裂。 |
| D4 | 结构 | **门派向套装** | 扁平实用：收集欲弱。词条驱动：随机+四维+强化三者叠加最易失衡。**已接受的后果**：装备选择可能沦为门派附庸——由 §4.4 的通用款与"凑齐才生效"缓解。 |

## 3. 数据模型

### 3.1 槽位

四个槽位，各主推 1–2 个属性，依据是四维在**现有公式**里的真实分工：

| 槽位 (`slot`) | 主推属性 | 依据（现有代码） |
|---|---|---|
| `weapon` 兵器 | 内力 + 根骨 | `power()` 中内力权重最高（×1.2） |
| `armor` 护具 | 根骨 | `maxHp = 60 + gengu × 6`；`foeTurn` 防御 = `gengu × 0.4` |
| `boots` 鞋履 | 身法 | 闪避 `shenfa × 0.012`；脱身 `shenfa × 0.02` |
| `charm` 佩饰 | 悟性 | 闭关收益 `wuxing × 0.06` |

### 3.2 装备条目（`wuxia-content.js` 的 `GEAR` 数组）

```js
{
  id: 'sword_general_t0',        // 全局唯一
  name: '粗铁刀',
  slot: 'weapon',                // weapon | armor | boots | charm
  sect: null,                    // null = 通用款；否则为门派 id
  tier: 0,                       // 0 凡品 | 1 精品 | 2 珍品
  bonus: { neili: 1, gengu: 1 }, // 四维加成，键必须属于 {neili,gengu,shenfa,wuxing}
  price: 80,                     // 商城价（银两）；掉落获得时用于重复折算
}
```

- `sect: null` → **通用款**，任何门派可穿，商城常驻。
- `sect: 'shaolin'` → **门派款**，本门弟子穿齐才吃套装加成；非本门可穿但无套装效果。
- `tier` 决定**强化上限**（见 §4.2），这是防止"无限银两换无限战力"的关键。

### 3.3 状态（`state.jianghu.gear`）

```js
gear: {
  owned:    { 'sword_general_t0': { lvl: 2 } },   // 已拥有装备 → 强化等级
  equipped: { weapon: 'sword_general_t0', armor: null, boots: null, charm: null },
}
```

加入 `defaultState().jianghu`，由 `ensureFields` 为旧存档补齐：

```js
gear: { owned: {}, equipped: { weapon: null, armor: null, boots: null, charm: null } }
```

## 4. 数值设计

### 4.1 品阶与商城定价

| 品阶 | `tier` | `bonus` 四维合计 | 强化上限 | 商城价（银两） |
|---|---|---|---|---|
| 凡品 | 0 | +2 | 2 级 | 60–120 |
| 精品 | 1 | +4 | 4 级 | 250–400 |
| 珍品 | 2 | +6 | 6 级 | 600–900 |

定价锚点：现有唯一出口"学满本门武学"约需 5,000–12,000 两；敌方赏银 18–200 两/次，
每天最多 6 次闯荡。装备定价与强化曲线按同一量级配置。

上表数值为**设计带**；每件装备的 `bonus` 与 `price` 在内容编写时按此带取值，
并在实施计划中逐件列明（不接受"待定"上线）。

### 4.2 强化

- 第 n 级（n 从 1 起）消耗：`round(item.price × 0.25 × n)` 银两。
- 效果：**只给该装备的主属性 +1**。主属性 = `bonus` 中数值最大的键
  （并列时按 `neili > gengu > shenfa > wuxing` 固定顺序取，保证确定性）。
- 上限：`tier` 值（凡 2 / 精 4 / 珍 6）。达到上限后按钮禁用并提示"已至极限"。
- 珍品满强化单件约 `600×0.25×(1+2+3+4+5+6) = 3,150` 两，四件约 12,600 两，
  比"学满本门武学"厚一档，构成够重但非天文数字的终局出口。

### 4.3 套装加成

- 复用门派**现有的身份属性**（少林 `bonus` 为根骨、武当内力、唐门身法），
  取 `Object.keys(sc.bonus)[0]`，**不新增内容字段**。
- 已穿装备中 `sect === 本门` 的件数：`≥2` → 该属性 +1；`≥4` → 该属性 +2。
- **凑齐才生效**，因此凑齐之前仍有过渡搭配的选择空间。

### 4.4 通用款的作用（保住决策空间）

因为门派不可改投（`joinSect` 拒绝改换），门派向套装会让装备选择趋同。
因此设计要求：**通用款必须在四个槽位都提供有竞争力的定位**
（如纯堆根骨的高气血路线、纯堆身法的高闪避路线），使玩家在"套装 vs 通用特化"
之间仍有取舍。

### 4.5 叠加顺序（`stats()` 唯一真源）

```
stats() = 自身四维（修炼所得）
        + 门派加成 (sc.bonus)
        + 宠物伙伴加成 (partners()，按 label 去重、取最高不叠加)
        + 装备加成 (gearBonus()，含强化)
        + 套装加成 (setBonus())
```

每一层都是纯加法，顺序固定，保证可预期、可断言。

### 4.6 数值硬约束（调参不得突破）

| 来源 | 四维合计 |
|---|---|
| 自身修炼（长期） | ~15 |
| 门派 | +4 |
| 宠物伙伴 | +2 |
| 装备四槽珍品满强化 | **+48** |
| 套装（4 件） | +2 |
| **合计** | **~71** |

装备把四维推到约 **2.4 倍**：钱能显著变强，但修炼与境界仍占基础盘。
**已接受的后果**：事件属性门槛最高为「身法 14」，满配装备可轻松越过。
这是决策 D2 的直接结果，此处显式记录而非含糊。

## 5. 获取途径

### 5.1 掉落接入点（复用现有函数，不新增流程）

| 接入点 | 形式 | 位置 |
|---|---|---|
| 切磋胜利 | `FOES[i].drops: [{ gear: 'id', chance: 0.15 }]` | `finishDuel()` 胜利分支 |
| 事件奖励 | `outcome.gain.gear: 'id'`（确定性） | `applyOutcome()` |

### 5.2 重复掉落折算

已拥有同名装备时，不重复入库，转为 `round(item.price × 0.3)` 银两，
并写入 `log` 与 `showToast` 提示。避免"打到重复 = 白打"。

### 5.3 货架分工

| 类型 | 获取方式 |
|---|---|
| 通用款 | 商城**常驻**（银两出口主力） |
| 本门门派款 | **掉落为主** + 商城**溢价保底**（精品 350 两，对比通用 250 两） |
| 别派门派款 | 不显示、不出售，且**不配进任何掉落表**（避免无法使用的死奖励）。`sect` 字段保留跨门派语义，仅为未来玩法留口 |

### 5.4 初始内容量

- 通用款：4 槽 × 3 品阶 = **12 件**
- 门派款：3 门派 × 4 槽 = **12 件**（精品档）
- 合计 **24 件**，全部以数据形式放在 `wuxia-content.js`。

## 6. 操作与界面

### 6.1 四个动作（挂在 `Jianghu`，与 `cultivate`/`learn`/`spar` 同构）

全部遵循既有模式：校验 → `showToast` 提示 → 改状态 → `log` → `save` → `rerender`。

| 动作 | 校验 | 效果 |
|---|---|---|
| `buyGear(id)` | 装备存在、别派不售、银两足够、未拥有 | 扣银两，写入 `owned[id] = { lvl: 0 }` |
| `equipGear(id)` | 已拥有、槽位合法 | 写入 `equipped[slot] = id`（旧件仍留在 `owned`） |
| `unequipGear(slot)` | 槽位合法 | `equipped[slot] = null` |
| `upgradeGear(id)` | 已拥有、`lvl < tier 上限`、银两足够 | 扣 `round(price×0.25×(lvl+1))`，`lvl + 1` |

### 6.2 界面

江湖页 `render()` 在「闭关」卡片之后、武学之前插入三块：

1. **装备** — 4 个槽位，显示已穿装备名 / 强化等级 / 该槽加成，并提供「卸下」
2. **行囊** — `owned` 中未穿戴的装备，显示属性与「穿戴」「强化」按钮
3. **货栈** — 可购列表（通用款 + 本门门派款），显示价格与「购入」

**不修改工作台原有商城**，避免金币与银两两套货币在同一界面混淆。

## 7. 集成点

### 7.1 `ensureFields` 兼容

`gear` 作为 `jianghu` 的直接子键，`ensureFields` 会为旧存档补齐
（其内层循环会补 `jianghu` 的每个缺失子键）。`gear.owned` / `gear.equipped`
若整体缺失则补默认值。

### 7.2 `sanitize()` 必须扩展

延续子项目 0 建立的自愈模式，否则会出现整页白屏：

| 场景 | 处理 |
|---|---|
| `owned` 的键指向已删除的装备 id | 删除该键 |
| `equipped[slot]` 指向已删除的装备 | 卸下（置 null） |
| `equipped[slot]` 指向不在 `owned` 里的 id | 卸下（置 null） |
| `equipped` 出现非法槽位键 | 删除该键 |
| `owned[id].lvl` 超过该装备当前品阶上限 | 截断到上限 |

自愈需**幂等**，且清理时写入 `log` 说明，不静默吞掉玩家资产。
健康的存档必须**一字不动**（有断言保护）。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 装备抬高 `power()`/`maxHp()` 后现有 6 个敌人被碾压 | 本轮**不加新敌人**；spec 记录"敌人数值需在子项目 3 重标" |
| 强化无上限 → 无限银两换无限战力 | 已用**品阶挂钩上限**（最高 6 级）堵住 |
| 装备并入四维后越过事件属性门槛 | 决策 D2 的既定后果；靠 §4.6 的数值纪律限制幅度 |
| 门派向套装压缩装备选择 | §4.4 要求通用款提供等价竞争力的定位 |
| 存档引用的装备被删 → 页面白屏 | §7.2 自愈扩展 + 断言 |
| 实测发现装备主导 | 只调 `bonus` 数字（纯数据），不动规则 |
| `jianghu.js` / `wuxia-content.js` **从未提交过**（git 未跟踪），有丢失风险 | 实施前先提交基线，让本轮改动可回滚、可对比 |

## 9. 测试策略

本项目已有既定约定（子项目 0 建立），本轮**沿用而不另造**：

- `tests/jianghu-harness.mjs` — 把 `wuxia-content.js` + `jianghu.js` 装进 vm 沙箱、
  冒充宿主 API（`getState`/`saveState`/`showToast`/`todayStr`），**穷举每条事件分支与
  每场切磋**，产出 `{ engineProblems, contentProblems, coverage, engineChecks }` 报告。
  它只负责跑与记录。
- `tests/test_jianghu.py` — pytest 断言上述报告的问题清单为空，并校验工作台 HTML 的
  真实接线（江湖页签、`jianghu` 存档字段、打卡产出）。当前 **13 项通过**。

### 本轮扩展

**`tests/jianghu-harness.mjs`：**

1. 内容校验新增 `GEAR` 表：`id` 唯一、`slot` ∈ 四槽、`bonus` 的键 ∈ 四维且值为正整数、
   `tier` ∈ {0,1,2}、`price` > 0、`sect` 要么 `null` 要么存在于 `SECTS`。
2. 掉落引用闭合：`FOES[].drops[].gear` 与 `outcome.gain.gear` 都能在 `GEAR` 里找到，
   且**不指向别派门派款**（避免无法使用的死奖励）。
3. 引擎试跑新增装备路径：
   - `buyGear`：银两不足被拒 / 别派门派款被拒 / 成功扣款并入库
   - `equipGear`：穿入正确槽位 / 替换后旧件仍留在 `owned`
   - `unequipGear`：卸下后 `gearBonus` 相应下降
   - `upgradeGear`：超上限被拒 / 缺银两被拒 / 成功后主属性 +1
   - `gearBonus`：多槽叠加正确；**强化只加到主属性**
   - `setBonus`：1 件不生效、2 件 +1、4 件 +2 的边界
   - `stats()`：五层叠加顺序与总和正确
4. **数值纪律**：四槽珍品满强化的四维合计恰为 +48。
5. 不变量：银两不为负、四维无 NaN。

**`tests/test_jianghu.py`：** 为上述各项添加断言，保持"问题清单必须为空"的风格。

**存档自愈（`sanitize()`）：** 上述 `owned`/`equipped` 的四种失效场景与幂等性
由 harness 试跑覆盖、由 pytest 断言，具体为：

- `owned` 指向已删装备 → 不崩且被清理
- `equipped` 指向已删装备 → 自动卸下
- `equipped` 指向不在 `owned` 的 id → 自动卸下
- 非法槽位键 → 被丢弃
- `lvl` 超上限 → 被截断
- 自愈幂等；健康存档一字不动

### 过渡期债务（需在计划中处理）

本会话为定位子项目 0 的缺口，临时写了两个**只能 `node` 单独跑、不在 pytest 入口内**的
脚本：`tests/jianghu-verify.mjs`（70 项）与 `tests/jianghu-gaps.mjs`（35 项）。
它们断言有效但会随流程腐化。计划中择一处理：

  ——最省事，保留既有断言，并让它们进入唯一入口；
- (b) 把断言搬进 harness + pytest ——最统一，但需改写。

## 11. 验收标准

1. 旧存档打开江湖页不报错，`gear` 字段被自动补齐。
2. 银两可以持续花出去：购买通用款与强化都真实扣减 `taels`。
3. 穿戴与卸下立即影响 `stats()` 与界面显示的加成合计。
4. 强化超过品阶上限时被拒绝并提示；银两不足时被拒绝。
5. 四槽珍品满强化的四维合计为 +48（数值纪律断言之）。
6. 删除 `wuxia-content.js` 里任意装备条目后，旧存档仍能打开江湖页，
   失效引用被自愈并记录到日志。
7. 已有的 70 项玩法断言与 35 项自愈断言继续全绿。
